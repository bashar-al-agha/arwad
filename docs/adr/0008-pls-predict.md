# ADR-0008: PLSpredict, cross-validated prediction for PLS-SEM

**Status:** Accepted, 2 November 2026 (amended 3 and 13 November 2026) · **Functions:** `aw_predict_pls()`, `aw_q2_predict()` in [`r/R/predict.R`](../../r/R/predict.R); `aw_assess_cvpat()`, `aw_assess_cvpat_compare()` in [`r/R/cvpat.R`](../../r/R/cvpat.R) · **Tests:** [`r/tests/testthat/test-predict.R`](../../r/tests/testthat/test-predict.R), [`r/tests/testthat/test-cvpat.R`](../../r/tests/testthat/test-cvpat.R)

## Context

A PLS-SEM study must show out-of-sample predictive power. The PLS-SEM Primer (Hair, Hult, Ringle and Sarstedt, 4th ed., pp. 201–209) and the project lead's PLS-SEM protocol (rule 60) require PLSpredict (Shmueli, Ray, Velasquez Estrada and Chatla, 2016; Shmueli et al., 2019) with 10 folds and 10 repetitions, earliest antecedents and a fixed seed, judged against the linear-model (LM) benchmark, and the cross-validated predictive ability test (CVPAT; Liengaard et al., 2021; Sharma et al., 2023) on the same cross-validated predictions. `seminr::predict_pls()` re-estimates the model on every training set in R: on the reference laptop, 10 folds × 10 repetitions of the four-construct ECSI model of `seminr`'s examples take 9.4 s and leave-one-out cross-validation of its 250 cases 11.7 s, about 47 ms per training set. The compiled PLS-SEM kernel of [ADR-0006](0006-pls-sem-engine.md) already estimates any set of samples given as columns of an index matrix; a training set is such a sample.

## Decision

1. **Function.** `aw_predict_pls(model, technique = predict_DA, noFolds = NULL, reps = NULL, cores = NULL)`, a drop-in for `seminr::predict_pls()` with its arguments and defaults, returns the object `predict_pls()` returns, bit for bit (class `predict_pls_model`), plus `native`.
2. **Folds,** as black-box tests of `seminr` 2.6.0 showed: each repetition draws `sample(n)` from the caller's random-number stream and cuts the shuffled cases into the folds of `cut(seq(1, n), breaks = k, labels = FALSE)`; leave-one-out (`noFolds = NULL`) shuffles too. A training set is the shuffled data without the fold, in shuffled order (the order sets the rounding), estimated with the model's own `maxIt` and stop criterion; a bootstrap, by contrast, uses `seminr`'s defaults ([ADR-0006](0006-pls-sem-engine.md)). The kernel estimates all training sets of one size in one call (fold sizes differ by one case at most), on `cores` processes if asked.
3. **Prediction of held-out cases,** in R after the kernel, as `predict.seminr_model()` computes it: indicators standardised with the training means (`colMeans()`) and `scale()`'s standard deviations (not `sd()`); each construct's composite scores as one matrix-vector product over its own indicators, `Z[, k] %*% w[k]`; each endogenous construct, after its antecedents `a` (in the model's construct order), `P[, a] %*% B[a, j]` from the predicted scores (earliest antecedents) or `S[, a] %*% B[a, j]` from the composite scores (direct antecedents); indicators `P %*% t(L)`, times the standard deviations, plus the means. The shapes of these products are part of the rule (amendment of 3 November 2026). The predicted indicators are those of the endogenous constructs, the constructs in the order in which they first appear as targets in the structural model.
4. **LM benchmark:** `.lm.fit()` with an intercept on the raw training data, predictions `X %*% b` out of and in sample (not the fitted values `y - e`, which round differently), one endogenous construct at a time. Earliest antecedents: each endogenous construct's indicators regressed on the indicators of every exogenous construct, including one that does not reach it; Arwad computes one `.lm.fit()` of all endogenous indicators, which gives the same coefficients because it solves each column on its own, and multiplies one construct's columns at a time. Direct antecedents: one fit per endogenous construct, on the indicators of each direct antecedent in turn, the antecedents in their order in the structural model (ordering them as the constructs are declared changes the rounding in 11 of the 39 direct-antecedent test models).
5. **Aggregation.** A case's in-sample prediction is the long-double sum of the predictions of the k − 1 models it trained, divided by k − 1 (`rowSums()`; `mean()` and `rowMeans()` differ). Item predictions are averaged over the repetitions with `mean()`, element by element, by a small compiled unit that calls `mean()` once per element (Arwad's runtime follows GNU R's algorithm, extended precision included; `apply()` with `mean()` took about 0.12 s per call, a fifth of a 10 × 10 run), and with one repetition the predictions themselves plus 0, which is `mean()` of one value (it turns −0 into 0) (`rowMeans()` agrees on Windows and Linux, where R sums in x87 long double, but not on macOS arm64, which has no long double, as the first continuous-integration run showed); the composite predictions are those of the **last** repetition only, a `seminr` quirk reproduced on purpose; `actuals_star` is the model's construct scores. The data's row names label the item predictions of a single run (`reps = NULL`) and none once `reps` is given, even 1; with a single predicted indicator `seminr`'s matrices drop to vectors (named for a single run) and, with repetitions, the benchmark's predictions stay n × 1 matrices. Residuals are the data minus the predictions.
6. **Scope.** Native: models of composites (Mode A and Mode B, path weighting) without interaction terms. Passed to `seminr::predict_pls()` itself: models with `reflective()` constructs, which `seminr` 2.6.0 predicts with the model-implied conditional expectation of de Rooij et al. (2023), a different algorithm; interaction terms; every call under `seminr` < 2.6.0, which repeated the same folds in each repetition and whose `predict_pls()` can loop forever with earliest antecedents on some structural models (its 2.6.0 NEWS reports the fix; a run of the tests here under 2.5.0 did not finish in 22 minutes of computing, against under 3 minutes under 2.6.0); other techniques; a rank-deficient benchmark regression; and whatever the kernel declines. Before handing over, the random-number state is restored, so `seminr` draws the same folds.

## Validation

All 79 models of composites in the test set (Mode A and Mode B, 2 to 7 constructs, 40 to 800 cases, shuffled declaration and path orders), earliest and direct antecedents alternately, 5, 7 and 10 folds: the whole object identical to `predict_pls()` with `identical(num.eq = FALSE)`, and the random-number state after the call identical. Also tested: 1, 2 and 3 repetitions, leave-one-out, data with row names of their own, a single predicted indicator with and without repetitions, `cores = 2`, the printed `summary()`, and the hand-over of consistent-PLS and interaction models. The continuous-integration runs on Linux, macOS (arm64) and Windows are the equivalence gate on other platforms (the job with `seminr` 2.5.0 skips these tests); on this laptop's x87 long double, `rowMeans()` and `mean()` give the same repetition averages in every test, so the arm64 runs, which have no long double, decide between them. Locally the tests also pass, natively, under a copy of R 4.6.0 whose BLAS and LAPACK are OpenBLAS 0.3.26, the library of the Linux job (amendment of 3 November 2026).

## Clean-room record

Only `seminr` 2.6.0's help pages (`?predict_pls`, `?predict.seminr_model`, `?predict_EA`), its `NEWS.md` and the outputs of its functions were used; no `seminr` source code was read. The shapes of the products (amendment of 3 November 2026) were found the same way: by comparing candidate products with `seminr`'s outputs under OpenBLAS.

## Amendment, 3 November 2026: the shapes of the matrix products

The first continuous-integration runs failed on Linux on almost every model while Windows and macOS passed. The Linux job's R uses OpenBLAS 0.3.26, which the runner installs as the system BLAS. R's reference BLAS sums each product term by term, in order, so one wide product with zero weights, a narrower product and a matrix-vector product all give the same result. OpenBLAS uses different kernels for matrix-matrix and matrix-vector products and adds the terms of the latter in blocks, so the forms round differently. A copy of R 4.6.0 with OpenBLAS 0.3.26 (Haswell kernels) on the reference laptop reproduced the failures. Under it, candidate products were compared with the outputs of `predict()` and `predict_pls()`, using a fold model of each test model (90% of its cases):

- composite scores, one construct at a time: 79 of 79 models (one product `Z %*% W` with the zero weights: 9);
- endogenous scores over the antecedents only: 79 of 79 with earliest and with direct antecedents (over the whole path column: 49 and 45; explicit products: 67 and 66);
- the benchmark under earliest antecedents, one regression per endogenous construct on the indicators of every exogenous construct: 80 of 80 (one product for all endogenous indicators: 57; regressions on the exogenous constructs that reach the construct: 79, failing the one model in which an exogenous construct does not).

Items 3 and 4 state the result. The tests now include that model, and when the fold-prediction test fails, its message names which of these forms would have matched.

The compiled average of the repetitions (item 5) uses the `mean()` of Arwad's runtime, which matches GNU R's on x86-64 and arm64 for NA, NaN, signed zeros and infinities. One difference turned up in its test on macOS arm64, where there is no extended precision: finite values whose sum overflows. For (−0, v, v) with v = `0x1.1ccf385ebc8a3p+1023` (R's parse of `1e308` there), GNU R 4.6.0 returned `0x1.7bbef5d3a60dap+1022`, one unit in the last place above the correctly rounded mean `0x1.7bbef5d3a60d9p+1022`. Arwad's runtime returns the correctly rounded value, and so do both on x86-64. Six formulas tried in double arithmetic all give the correctly rounded value, so GNU R's arm64 result is not matched yet. Predictions, which are values of the indicators, never come near that range; the test keeps its extremes below it.

## Amendment, 13 November 2026: CVPAT and $Q^2_{\text{predict}}$

1. **$Q^2_{\text{predict}}$ (`aw_q2_predict()` and `out$q2_predict`).** Shmueli et al. (2016, 2019) and the PLS-SEM Primer (3rd ed., 2022, pp. 201–209) define the indicator-level $Q^2_{\text{predict}}$ as one minus the ratio of the out-of-sample sum of squared prediction errors of the PLS model to that of the indicator-average (IA) benchmark, where each held-out case is benchmarked against the arithmetic mean of the indicator in its own training fold (`colMeans()` of the training cases, already computed per fold by `aw_pls_train_scale()`). Across multiple repetitions, the training-fold indicator means are averaged over the repetitions with `aw_pls_rep_mean()`, matching how `PLS_out_of_sample` is averaged. `aw_predict_pls()` stores the named numeric vector as `out$q2_predict` on every native `predict_pls_model` (leaving `names(want)` unchanged for `seminr::predict_pls()` compatibility and omitting `q2_predict` when `native = FALSE`), and `aw_q2_predict(x, technique = predict_DA, noFolds = NULL, reps = NULL, cores = NULL)` either extracts `x$q2_predict` from a native `predict_pls_model` or computes it from an `estimate_pls()` model (when `aw_predict_pls()` delegates to `seminr::predict_pls()`, reconstructing the training-fold indicator means from the same fold draws—including `seminr` < 2.6.0's repeated single-fold draw when `reps > 1`—or returning `NULL` when `seminr::predict_pls()` returns `NULL` on higher-order models).
2. **CVPAT (`aw_assess_cvpat()` and `aw_assess_cvpat_compare()`).** In [`r/R/cvpat.R`](../../r/R/cvpat.R), `aw_assess_cvpat(seminr_model, testtype = "two.sided", nboot = 2000, seed = 123, technique = predict_DA, noFolds = NULL, reps = NULL, cores = NULL)` and `aw_assess_cvpat_compare(established_model, alternative_model, testtype = "two.sided", nboot = 2000, seed = 123, ...)` implement the cross-validated predictive ability test of Liengaard et al. (2021) and Sharma et al. (2023) as drop-in replacements for `seminrExtras::assess_cvpat()` and `seminrExtras::assess_cvpat_compare()`.
3. **Losses and fold draws.** Black-box probing of `seminrExtras` 1.0.4 showed that its CVPAT functions call `seminr::predict_pls(..., cores = cores)` once per repetition (`R = ifelse(is.null(reps), 1L, reps)` sequential calls with `reps = NULL` on the continuous RNG stream; in `assess_cvpat_compare()`, all `R` repetitions of `established_model` run first, then all `R` repetitions of `alternative_model`). In each repetition, the case-level loss for endogenous construct $c$ (in the order in which constructs first appear as targets in `smMatrix`, aligned to `established_model`'s target order in `assess_cvpat_compare()`) is `rowMeans()` of the squared out-of-sample indicator residuals (`PLS_out_of_sample_residuals` and `lm_out_of_sample_residuals`), and the `Overall` column is `rowMeans()` across the $J$ endogenous construct losses (unweighted mean of construct losses, not indicator-weighted). Across multiple repetitions, the per-observation construct losses are summed over the repetitions in order and divided by $R$, and the `Overall` column is taken after that averaging (averaging each repetition's `Overall` instead differs in the last bits). In `assess_cvpat()`, the IA benchmark centers each endogenous indicator by its full-sample mean on `seminr_model$data`. Native composite models share `aw_pls_cv_fits()` and the fold-prediction helpers (`aw_pls_spec()`, `aw_pls_order()`, `aw_pls_run_cores()`, `aw_pls_train_scale()`, `aw_pls_fold_predict()`, `aw_pls_lm_sets()`) with `aw_predict_pls()`, drawing the exact same `sample(n)` fold permutations and estimating the training folds on `cores` worker processes when `cores > 1`. Models outside the native composite scope (such as `reflective()` constructs or interaction terms) delegate to `seminrExtras` when installed and `testtype != "less"`, and otherwise compute the per-repetition losses via `seminr::predict_pls()`.
4. **Compiled paired-bootstrap t-test (`aw_cvpat_boot_kernel()`).** After the fold losses, bootstrap resampling runs across $2(J + 1)$ slots in order `[IA Overall, LM Overall, IA endo_1..J, LM endo_1..J]` for `assess_cvpat()` and $J + 1$ slots in order `[Overall, endo_1..J]` for `assess_cvpat_compare()`. In each slot, with `D = L_benchmark - L_PLS` (or `D = L_alternative - L_established`), every one of the `nboot` replicates draws two resamples of the $n$ cases from the random-number stream (`sample.int(n, n, replace = TRUE)` each); the first enters no reported value, and the second gives the mean of the centred differences, `mean((D - mean(D))[s2])`. `T = mean(D) / sd(bm)` over those `nboot` means, with $n - 1$ degrees of freedom. The centring was found from the values `seminrExtras` passes to `var()`: averaging the uncentred `D` gives the same standard error only up to the last bits, which `Boot T value` and `Boot P Value` (15 significant digits) can show. Arwad compiles this loop via `aw_compile()` into `aw_cvpat_boot_kernel(D, B)` (`name = "aw_cvpat_boot"`, zero bailouts), called with the centred `D`; it draws $2B$ resamples, advancing `.Random.seed` identically, and averages each second one with the `mean()` of Arwad's runtime, which follows GNU R's extended-precision algorithm.
5. **Formatting, validation and speed (`testtype = "less"`).** Both functions return `table_output` matrices with the exact `dim`, `dimnames`, `comment` and `class` attributes of `seminrExtras` 1.0.4; `aw_assess_cvpat()` rounds columns 1–3 with `as.numeric(format(col))` (7 significant digits) and stores columns 4–5 with `as.numeric(as.character(col))` (15 significant digits), while `aw_assess_cvpat_compare()` stores all 5 columns with `as.numeric(as.character(col))`. The mean losses are `colMeans()` for the construct rows and `mean()` for the `Overall` row, and `Diff` is the difference of those means, as the values `seminrExtras` passes to `mean()` showed; `mean()` adds a correction pass, so on macOS arm64, where R has no extended precision, the two differ in the last bit, which the 15-digit columns of `assess_cvpat_compare()` show (its first continuous-integration run there failed on the `Overall` row's `Diff` until this rule was followed). For `testtype = "two.sided"` (`2 * pt(-abs(T), df = n - 1)`) and `testtype = "greater"` (`pt(T, df = n - 1, lower.tail = FALSE)`), `aw_assess_cvpat()` matches `seminrExtras` 1.0.4 across all 79 composite models in the test set and `aw_assess_cvpat_compare()` matches across competing composite model pairs (including reordered target constructs, Mode A vs Mode B endogenous weights, and reordered indicators) under both R's reference BLAS and OpenBLAS 0.3.26 (the whole table `identical()`, `Boot T value` and `Boot P Value` included, and the same `.Random.seed` and warnings). For `testtype = "less"`, where `seminrExtras` 1.0.4 fails with an unbound-variable error (`object 'p_value_perc_t' not found`), Arwad computes the lower-tail p-value `pt(T, df = n - 1, lower.tail = TRUE)`. No speed is claimed until the CVPAT benchmark under `bench/phase2/` has been run as [BENCHMARK_METHOD.md](../BENCHMARK_METHOD.md) requires.
6. **Clean-room record (amendment).** Only the help pages (`?seminrExtras::assess_cvpat`, `?seminrExtras::assess_cvpat_compare`), black-box input/output and `.Random.seed` probes of `seminrExtras` 1.0.4, and the values it passes to base R's `mean()`, `var()`, `pt()` and `sample()` during a call (logged with `trace()`: argument values only, no call expressions) were used; no `seminr` or `seminrExtras` source code was read.

## Consequences

- PLSpredict, $Q^2_{\text{predict}}$ and CVPAT run at compiled speed and return what researchers report from `seminr` and `seminrExtras`, so `summary()`, `table_output` printing and downstream code are unchanged.
- The bootstrap, the jackknife, cross-validated prediction and the CVPAT paired bootstrap share the compiled toolchain, with zero bailouts.
